## 一、先明确中文地名的典型不规范场景

你遇到的问题本质是**中文地理实体链接（Geo-Entity Linking）**，常见干扰项包括：

1. **同音 / 近音字错误**：如 “锦洲”→锦州、“孟良固”→孟良崮、“台儿装”→台儿庄；
2. **简称 / 俗称 / 旧称**：如 “北平”→北京、“奉天”→沈阳、“苏中”→苏中解放区、“津浦路”→津浦铁路；
3. **错字 / 漏字**：如 “徐洲”→徐州、“娘子关” 写作 “娘孑关”；
4. **不规范音译**：如外文地名 “库尔斯克” 写成 “库尔期克”、“基辅” 写成 “基普”；
5. **同名歧义**：全国有数百个 “李庄”“张村”，仅靠名字无法定位。

## 二、三级解决链路（适配低精度态势图场景）

### 1. 第一级：LLM 前置语义纠错归一化

这是成本最低、见效最快的第一道关卡，GLM-5.3、DeepSeek V4 等中文大模型完全可以胜任。

- **做法**：给 LLM 设定专门的系统提示，要求它结合战报上下文，将所有不规范地名统一转换为标准行政 / 地理名称，并输出置信度。
示例提示逻辑：
> 
> 你是军事战史地名归一化助手。请从文本中提取所有地名，将同音字、错字、旧称、简称修正为当代标准地名；结合战役背景判断同名地名的正确位置；对不确定的地名标记 [低置信度]。
- **优势**：能利用上下文语义解决大部分常见错误。比如看到 “辽沈战役 锦洲 塔山”，会自动修正为 “锦州”，而不会匹配到南方的同名村镇。
- **局限**：生僻小地名、非常见音译会出现幻觉；同名歧义无法仅凭文本区分。

### 2. 第二级：中文地名库拼音模糊匹配（核心兜底）

这是解决同音字、错字的硬核心，不能完全依赖 LLM 的 “语感”。

- **原理**：提前准备一份带拼音、别名、旧称的中文地名库，对 LLM 输出的候选地名做**拼音匹配 + 编辑距离计算**，返回 TopN 候选标准地名。
- **核心匹配算法**：
  - 拼音转换：用 `pypinyin` 等工具将原始地名转为全拼 / 首字母，消除同音字差异；
  - 模糊匹配：用莱文斯坦距离（编辑距离）计算字形相似度，容错 1~2 个错字；
  - 别名匹配：内置旧称、俗称、简称对照表（如 “国府”→南京国民政府、“剿总”→对应剿总司令部驻地）。

### 3. 第三级：空间一致性校验（排除同名歧义）

针对 “同名多地” 的终极兜底，利用 “同一战役的地名必然在同一地理区域” 的基本逻辑做筛选。

- **简单做法**：将候选地名全部转为经纬度，计算两两之间的距离，剔除明显偏离集群的错误候选。
例如：战报同时出现 “徐州、蚌埠、碾庄”，如果 “碾庄” 匹配到了山西的同名村庄，距离徐州几百公里，直接排除，保留江苏徐州附近的碾庄。
- **进阶做法**：让 LLM 结合战役常识判断，比如 “孟良崮属于山东临沂蒙阴县”，自动匹配正确的行政归属。

## 三、阶段 1：文本解析与地名标准化管线

本阶段解决同音字、错译、旧称、同名歧义问题，是整个管线的准确性基础。

### 1. 流程总览

```
小说文本 → LLM提取地名+语义纠错 → 拼音模糊匹配 → 地理编码获坐标 → 空间聚类校验 → 标准化地名坐标集
```

### 2. 步骤 1：LLM 地名提取与语义纠错

**系统提示词（固定）**：

> 
> 你是边境军事小说地名标准化助手。请从输入文本中提取所有地理实体名称，严格执行以下规则：
> 
> 
> 1. 涉及中国藏南地区，必须使用民政部公布的标准汉字地名，禁止使用任何印方非法称谓；
> 2. 将同音字、错别字、旧称、不规范音译统一为国内通用标准译名；
> 3. 结合「喜马拉雅山地、中印边境、滇西边境」上下文，排除明显不符合地理范围的同名地点；
> 4. 输出 JSON 格式，包含字段：标准地名、原始文本、所属区域、置信度（高 / 中 / 低）。

**输入示例**：“我部从达旺出发，沿西山口南下，目标攻占德让宗”
**输出示例**：`[{"标准地名":"达旺","所属区域":"中国西藏藏南","置信度":"高"}, ...]`

### 3. 步骤 2：拼音模糊匹配兜底

针对 LLM 未识别的同音字、错字，用 Python 脚本做二级匹配：

1. 用 `pypinyin` 将原始地名转为全拼；
2. 用 `python-Levenshtein` 计算与标准地名库的拼音编辑距离；
3. 返回 Top3 候选，匹配度＞80% 自动采纳，低于阈值标记为待人工确认。

**核心代码片段**：

```
from pypinyin import lazy_pinyin
from Levenshtein import ratio

def fuzzy_match_place(raw_name, standard_places):
    raw_pinyin = ''.join(lazy_pinyin(raw_name))
    best_match = None
    best_score = 0
    for std_name in standard_places:
        std_pinyin = ''.join(lazy_pinyin(std_name))
        score = ratio(raw_pinyin, std_pinyin)
        if score > best_score:
            best_score = score
            best_match = std_name
    return best_match, best_score
```

### 4. 步骤 3：地理编码与坐标获取

- **中国境内（藏南、云南）**：调用天地图地名搜索 API，传入标准地名获取 WGS84 经纬度；
- **巴基斯坦、印度境内**：调用 GeoNames 本地数据库查询，或调用天地图国际版 API；
- 输出统一格式：`地名, 经度, 纬度, 地区类型`

### 5. 步骤 4：空间聚类校验（歧义终极排除）

利用「同一战役地名必然集中在同一地理片区」的逻辑，剔除错误匹配：

1. 计算所有点位的经纬度中心；
2. 用 Haversine 公式计算每个点到中心的实地距离；
3. 针对本区域设置阈值（如 200 公里），超出阈值的候选点位自动排除，返回次优候选。

### 6. 本阶段输出

标准化的结构化数据：`地名坐标列表 + 作战行动关系表（进攻/防守/交火） + 地图显示范围（经纬度边界框）`

## 五、阶段 3：AI 风格化重绘管线（ComfyUI 实现）

本阶段将生硬的矢量线稿转化为符合小说氛围的艺术化配图，核心是**用 ControlNet 保证地理结构不偏移**。

### 1. 流程总览

```
矢量线稿 → 线稿预处理 → ControlNet结构控制 → 图生图重绘 → 风格渲染 → 合规校验
```

### 2. 前置：线稿预处理

1. 将矢量线稿去色转为灰度图；
2. 增强线条对比度，确保国界、主要路线、地名轮廓清晰；
3. 可选择性保留地名文字，也可后期手动添加，避免 AI 乱改文字。

### 3. ComfyUI 核心工作流（精准控制版）

表格

| 节点 | 参数配置 | 作用 |
| --- | --- | --- |
| 加载线稿图 | 输入阶段 2 输出的 PNG | 基底参考 |
| ControlNet 1（Canny） | 权重：0.7~0.8；低阈值 50，高阈值 150 | 锁定国界、路线、点位的边缘结构 |
| ControlNet 2（可选 Lineart） | 权重：0.5~0.6 | 强化手绘线条质感 |
| 图生图重绘 | 重绘幅度：0.3~0.4；采样器：DPM++ 2M Karras；步数：20~28 | 风格迁移，同时保留核心地理结构 |
| VAE 解码 | 适配对应基础模型的 VAE | 提升色彩质感 |

> 
> **关键参数说明**：重绘幅度严禁超过 0.5，否则国界和路线会发生严重偏移；0.3~0.4 是兼顾风格与准确性的黄金区间。

### 5. 事后合规校验

AI 出图后，必须人工核对两项：

1. 藏南、阿克赛钦段国界线走向是否符合官方标准；
2. 关键地名位置是否出现大范围偏移。
如有偏差，调低重绘幅度或加强 ControlNet 权重后重新生成。

## 六、阶段 4：输出与最终质检

### 输出规格

- **主图**：1920×1080（正文插图）、3000×2000（封面 / 跨页）两种尺寸
- **格式**：PNG（无损）、JPG（压缩）双格式
- **命名**：`战役名_地点_风格.png`，便于管理

### 终检清单（主权合规必过项）

1. 藏南地区国界线走向符合中国官方标准；
2. 藏南地名全部使用民政部标准名称，无非法称谓；
3. 阿克赛钦地区边界画法正确；
4. 无其他损害国家领土主权的表述或标注。

## 七、MCP / Skill 封装方案（LLM 可调用工具化）

如果需要实现 LLM 一键调用生成，可将上述管线封装为两个核心 MCP 工具，接入 GLM/DeepSeek 的工具调用体系。

### 1. 核心 Skill 1：边境地名标准化工具

- **输入**：原始地名字符串 / 小说文本片段 + 大致区域（藏南 / 滇西 / 印巴）
- **内部执行逻辑**：LLM 语义纠错 → 匹配民政部藏南标准库 + 印巴译名词典 → 天地图 / GeoNames 获取坐标 → 空间聚类校验
- **输出**：标准地名 + WGS84 经纬度 + 置信度 + 候选列表
- **异常处理**：置信度低于 60% 返回人工确认提示，不强行匹配

### 2. 核心 Skill 2：态势图一键生成工具

- **输入**：地名坐标列表、作战行动关系、风格类型（军用 / 复古 / 卫星）
- **内部执行逻辑**：调用天地图 API 生成合规底图 → 叠加官方国界 → Python 脚本标绘军事要素 → 调用 ComfyUI API 执行风格化重绘 → 返回最终图片
- **输出**：最终态势图图片 URL + 基础图例说明

### 3. 完整调用链路示例

```
用户：生成一段藏南达旺地区反击战的态势图
  ↓
LLM调用【地名标准化工具】提取并修正所有地名，获取坐标
  ↓
LLM计算地图边界框，调用【态势图生成工具】，指定“军用图纸风格”
  ↓
工具返回生成的图片，LLM补充态势说明文字
  ↓
用户获得最终配图+文字解读
```

## 八、成本与优化建议

### 个人非商用成本核算

- 基础工具、数据源、AI 模型：全部开源免费；
- 天地图 API：个人开发者免费额度完全够用，超量也可通过离线本地库替代；
- 总成本：0 元，仅需投入时间搭建环境。

### 进阶优化方向

1. **批量生成**：将小说章节批量导入，自动按战役拆分生成多张态势图；
2. **地形增强**：叠加 SRTM 高程数据生成山体阴影，大幅提升边境山地的真实感；
3. **时间轴动画**：基于多帧态势图生成简单的行军推进 GIF，适合视频化创作；
4. **本地离线化**：将地名库、底图瓦片全部本地化部署，无需联网即可运行，保障内容安全。
