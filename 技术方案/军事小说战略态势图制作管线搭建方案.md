# 军事小说战略态势图制作管线搭建方案

> 版本：v1.0（2026-10-17）
> 来源：综合豆包方案（飞书 wiki：DqI2wLqZ8ilr29k0eETcmlbInl9）+ Trae 沙箱环境实测验证
> 场景：以真实地理为基底的军事小说配图 / 战史科普（示意级精度，非战术级）

---

## 1. 需求与范围

| 项 | 内容 |
|---|---|
| 输入 | 小说战斗段落文本（含中文/音译地名、部队番号、行动描述、时间线） |
| 输出 | 以真实地图为底，标注行军路线、交火位置、部队态势的战略态势图 |
| 精度要求 | 县级以上地名、主要山口河谷、国界走向准确；村镇级点位允许示意偏差 |
| 目标区域 | 巴基斯坦、印度、中国藏南、云南（喜马拉雅 / 喀喇昆仑 / 滇西横断山区） |
| 参考素材 | 工作区已备《国家意志（野狼獾）》全文，可作首批输入 |

### 核心痛点

1. **中文地名不规范**：同音字（"锦洲"→锦州）、错字漏字、旧称简称（"北平"→北京）、音译混乱（"史达林格勒"→斯大林格勒）；
2. **同名歧义**：全国数百个"李庄""张村"，仅靠名字无法定位；
3. **领土主权合规**：藏南地名与国界画法是红线，不可逾越；
4. **沙箱网络限制**：部分国际地图数据源不可达（见 §3 实测）。

---

## 2. 可行性结论

**可以承担。** 纯 LLM 无法独立完成 GIS 级工作，但可作为全程调度与内容核心；搭配轻量地理工具链（地理编码 + Python 绘图）即可低成本落地，AI 风格化（ComfyUI/SD）作为可选增效环节。

分工原则：

- **LLM 负责**：文本实体抽取、语义纠错、同名歧义预判、绘图提示词生成、整链调度；
- **工具链负责**：坐标获取（API/地名库）、底图渲染（matplotlib）、模糊匹配（pypinyin + Levenshtein）、空间校验（Haversine）；
- **人负责**：低置信度地名确认、国界线与藏南地名终检。

## 4. 管线总体架构

四层架构：**LLM 调度中枢 + 三大功能模块 + 双节点合规校验**

```
小说文本输入
    ↓
【LLM 调度中枢】实体抽取 + 地名标准化（三级纠错链路）
    ↓ ── 合规校验节点 1：藏南地名 / 译名合规性 ──
【模块 1】地理编码：分区域坐标获取 + 空间聚类校验
    ↓
【模块 2】合规底图生成 + 军事标绘（matplotlib 矢量渲染）
    ↓ ── 合规校验节点 2：国界线走向复核 ──
【模块 3】AI 风格化重绘（可选，ComfyUI 图生图 + ControlNet）
    ↓
终检清单 → 交付（PNG 静态图 / 交互 HTML）
```

## 6. 阶段 1：文本解析与地名标准化（三级纠错链路）

解决同音字、错字、旧称、音译混乱、同名歧义。**三级链路覆盖 95%+ 场景。**

### 6.1 流程

```
小说文本 → L1 LLM 语义纠错 → L2 拼音模糊匹配 → L3 空间聚类校验 → 标准化地名集
```

### 6.2 L1：LLM 前置语义归一化 + 主权校验

系统提示词模板（固定）：

> 你是边境军事小说地名标准化助手。请从输入文本中提取所有地理实体名称，严格执行：
> 1. 涉及中国藏南地区，必须使用民政部公布的标准汉字地名，禁止使用任何印方非法称谓；
> 2. 将同音字、错别字、旧称、不规范音译统一为国内通用标准译名（如"史达林格勒"→斯大林格勒）；
> 3. 结合「喜马拉雅山地、中印边境、滇西边境」上下文，排除明显不符合地理范围的同名地点；
> 4. 输出 JSON：`标准地名、原始文本、所属区域、置信度（高/中/低）`。

示例：输入"我部从达旺出发，沿西山口南下，目标攻占德让宗"
输出：`[{"标准地名":"达旺","所属区域":"中国西藏藏南","置信度":"高"}, ...]`

### 6.3 L2：拼音模糊匹配兜底（核心代码）

```python
from pypinyin import lazy_pinyin
from Levenshtein import ratio

def fuzzy_match_place(raw_name, standard_places):
    """拼音编辑距离匹配，消除同音字/错字差异"""
    raw_pinyin = ''.join(lazy_pinyin(raw_name))
    best_match, best_score = None, 0
    for std_name in standard_places:
        score = ratio(raw_pinyin, ''.join(lazy_pinyin(std_name)))
        if score > best_score:
            best_score, best_match = score, std_name
    return best_match, best_score   # >0.8 自动采纳，低于阈值转人工
```

标准地名库构成：民政部行政区划库（县级及以上）+ 藏南标准地名 CSV + 自制印巴译名词典 + GeoNames 中文对照。

### 6.4 L3：空间聚类校验（同名歧义终极排除）

利用"同一战役地名必然集中在同一地理片区"的逻辑：

1. 计算全部候选点位经纬度中心；
2. Haversine 公式计算各点到中心的实地距离；
3. 区域阈值设 200 km（本区域战役尺度），超阈值候选剔除、取次优；
4. 例："瓦弄"必须落在藏南察隅附近，匹配到内地同名村落即排除。

### 6.5 阶段输出（统一 schema）

```json
{
  "places":  [{"name": "达旺", "region": "藏南", "conf": "高", "lat": 0.0, "lon": 0.0}],
  "actions": [{"type": "进攻|迂回|撤退|防守", "from": "达旺", "to": "德让宗", "unit": "步兵第X师", "time": "D+2"}],
  "battles": [{"place": "西山口", "result": "交火", "time": "D+3"}],
  "bbox":    {"min_lon": 0.0, "min_lat": 0.0, "max_lon": 0.0, "max_lat": 0.0}
}
```

置信度低于阈值的地名输出**待确认清单**，不强行匹配。

## 7. 阶段 2：地理编码（坐标获取）

分区域选择数据源：

| 区域 | 首选 | 兜底 | 备注 |
|---|---|---|---|
| 中国境内（藏南、云南） | 天地图地名搜索 API | 阿里 DataV / 高德 | 官方服务，地名与国界合规 |
| 巴基斯坦、印度 | GeoNames 本地库 / API | LLM 内置地理知识 | 英文原名反查中文译名 |
| 生僻小地名 / 虚构地名 | LLM 上下文推断方位 | 坐标偏移 | "徐州以东 30 里的小镇"→按方位偏移落点，示意场景可接受 |

**坐标系注意**：高德/天地图部分服务返回 GCJ-02，绘图前统一转 WGS-84（`coord-convert` 或公式转换），避免叠加 GeoJSON 底图时整体偏移。

## 8. 阶段 3：合规底图生成与军事标绘

### 8.1 方案 A：全自动 Python 矢量方案（推荐，沙箱内零 key 可跑）

**底图**（matplotlib + GeoJSON）：

- 中国境内：DataV GeoAtlas 行政区划边界（省/市/县三级）；
- 印巴：GeoNames 点位 + Natural Earth 政区边界（需叠加官方国界线修正）；
- 地形增强（可选）：SRTM 高程渲染山体阴影，突出喜马拉雅/横断山特征；
- **强制操作**：叠加自然资源部官方标准国界线矢量层，覆盖底图原生边界。

**军事要素标绘规范**：

| 要素 | 样式 |
|---|---|
| 进攻路线 | 红色粗箭头（沿途经点平滑曲线） |
| 迂回穿插 | 红色带箭头虚线 |
| 撤退路线 | 蓝色虚线箭头 |
| 交火点 | 红色圆点 / 交叉符号 |
| 据点 | 方形（守军）/ 三角形（炮兵） |
| 指挥部 | 五角星 |
| 控制区 | 半透明色块（红=攻方，蓝=守方） |
| 标注 | 标准地名、部队番号、时间节点 |

**说明**：行军路线为"途经点连线"（文本只给 A→B→C），非真实道路轨迹；需沿真实道路需高德路径规划 API（增强项）。

**输出**：1920×1080 / 3000×2000 PNG 高清线稿，为阶段 4 重绘留余量。

### 8.2 方案 B：半手动 QGIS（非技术用户）

加载合规底图瓦片 + 官方国界层 → 导入地名坐标 CSV → 手动标绘 → 导出。适合单张精修，不适合批量。

### 8.3 交付形态

- **静态 PNG**：正文插图主力（matplotlib 直接导出）；
- **交互 HTML**：`html-report-presentation:html-report` skill 生成自包含页面，支持缩放、悬停查看战斗详情，适合复杂战役多路线场景。

## 9. 阶段 4：AI 风格化重绘（可选增效）

核心思路：**线稿重绘法**——矢量线稿保证地理结构，AI 只做质感。

```
矢量线稿 → 灰度化/对比度增强 → ControlNet 结构控制 → 图生图重绘 → 合规复核
```

| 节点 | 参数 |
|---|---|
| ControlNet Canny | 权重 0.7~0.8，低阈值 50 / 高阈值 150 |
| ControlNet Lineart（可选） | 权重 0.5~0.6 |
| 图生图重绘幅度 | **0.3~0.4，严禁超 0.5**（否则国界/路线偏移） |
| 采样器 | DPM++ 2M Karras，步数 20~28 |

分风格提示词模板（适配本区域山地特征）：

**① 写实军用图纸（硬核军事小说）**
> 俯视视角，高清军用作战地图，喜马拉雅高山峡谷地形，清晰等高线，深绿色河谷，灰白色雪山冰川，黑色实线标注中国官方标准国界线，红色粗箭头标注山地部队进攻路线，蓝色方块标记守军据点，黑色圆点标记交火位置，标准印刷体中文地名标注，泛黄纸张质感，军事档案风格，无多余装饰

**② 复古羊皮卷（历史/谍战向）**
> 俯瞰视角，复古战争地图，泛黄羊皮纸质感，手绘墨线勾勒喜马拉雅山脉轮廓，土黄色底色，红色墨水绘制行军路线，褐色标注城池与山口隘口，毛笔字体地名，边缘有磨损痕迹，涵盖印度北部、中国藏南、云南西部区域

**③ 现代卫星战术（现代特种作战）**
> 卫星视角俯瞰战术地图，真实高原山地纹理，蓝灰色冷色调，发光红色箭头标注行军路线，闪烁光点标记交火位置，半透明绿色控制区域，HUD 界面元素，科技感军事指挥屏幕风格，覆盖中印边境藏南地区

AI 出图后必检：国界走向、关键地名位置；有偏移则调低重绘幅度或加强 ControlNet 权重重新生成。

## 10. Skill / MCP 封装方案

现有 MCP（GitHub/Gitee/飞书）无地图类服务，**不需要新增 MCP**。在 Trae 中的实际落地形态：

| 封装 | 内容 | 实现方式 |
|---|---|---|
| 地名标准化工具 | 输入：文本片段 + 区域 → 输出：标准地名 + 坐标 + 置信度 + 候选 | L1 由模型自身完成；L2/L3 为 Python 脚本（`RunCommand` 调用） |
| 态势图生成工具 | 输入：schema 化作战数据 → 输出：PNG / HTML | matplotlib 脚本 + 官方国界层叠加；交互版走 `html-report` skill |

调用链示例：

```
用户：生成一段藏南达旺地区反击战的态势图
 → 模型抽取并修正地名（L1），调脚本做 L2/L3 校验拿坐标
 → 模型计算边界框，调态势图生成脚本，指定风格
 → 返回 PNG + 图例说明，模型补充态势解读文字
```

## 11. 合规红线（终检清单，不可逾越）

1. 藏南地区国界线走向符合中国官方标准画法；
2. 藏南地名全部使用民政部公布的标准名称，无印方非法称谓；
3. 阿克赛钦地区边界画法正确；
4. 不使用未修正的 OSM / Google 默认中印边界图层；
5. 若公开传播发布，遵守《地图管理条例》相关要求（小说内部非商用配图要求相对宽松，公开传播需送审）。

## 13. 风险与限制

| 风险 | 影响 | 缓解 |
|---|---|---|
| 生僻小地名 / 音译变体无法解析 | 点位缺失 | LLM 方位推断 + 待确认清单人工补录 |
| OSM 类底图被沙箱屏蔽 | 无法用街路网/卫星底图 | 矢量底图路线本就更适合战略图；卫星底图可走天地图影像层（L1） |
| 标准地图服务网站被屏蔽 | 官方底图文件无法沙箱内直接下载 | 本机下载后经 `.uploads` 上传，一次性动作 |
| 行军路线为示意连线 | 非真实道路轨迹 | 示意图场景可接受；需精确走位加高德路径规划（L2） |
| LLM 幻觉定位 | 坐标错误 | 三级链路 + 空间聚类校验 + 置信度门槛 |
| AI 重绘后地名/国界偏移 | 合规风险 | 重绘幅度 ≤0.4 + ControlNet + 出图后人工复核 |

## 附：与豆包原方案的差异说明

本方案在豆包方案基础上，结合 Trae 沙箱实测做了如下修正与增强：
